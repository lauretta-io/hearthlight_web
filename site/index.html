The Three Zoos

One product, three operator-facing catalogs.

Hearthlight separates model choice, event choice, and action choice so plugins can extend the system without turning the control plane into a tangle.

01

Model Zoo

Plugin-provided model registrations and mounted-model state that drive model bindings, inventory views, and source-specific runtime selection.

02

Trigger Zoo

Trigger catalog entries that define which runtime events can become rules, alerts, and future trigger-family expansions.

03

Connector Zoo

Connector catalog entries that define where actions go next, from notification paths to external systems and installable integrations.

Runtime architecture

A modular pipeline with a real control plane behind it.

1

Ingestor

Opens feeds, runs detection and tracking, and pushes structured frame bundles.

2

ReID

Resolves persistent identities for people and bags across camera-local tracks.

3

Anomaly

Applies pluggable anomaly adapters and emits normalized event records.

4

Association

Infers ownership, generates incidents, and keeps downstream resolution coherent.

FastAPI + React control plane

Operators save sources, model bindings, anomaly prompts, and alert rules through the web app before a `/start` command is published into the runtime.

RabbitMQ + Postgres backbone

RabbitMQ coordinates long-running services while Postgres stores both runtime entities and control-plane state across `runtime` and `control` schemas.
